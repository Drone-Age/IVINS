# Політика документації

Ця політика є нормативною для документації iVINS.

## Мовний контракт

Англійська версія є канонічною для автоматизації, машинного тлумачення, схем,
команд, ідентифікаторів та міжнародної інтеграції. Українська є обов’язковою
підтримуваною локалізацією кожного нормативного документа для людей.
Канонічний файл має назву `NAME.md`, український відповідник — `NAME.uk.md`.
Команди, шляхи, назви пакетів, версії, поля, hashes і теги не перекладаються.

Нормативну зміну завершено лише тоді, коли обидві мовні версії містять
технічно рівнозначні вимоги, оновлені в одному коміті, навігація чинна,
`PROCESS_VERSION` збільшено за `VERSIONING.md`, а зміну записано до
`CHANGELOG.md`.

Якщо переклади суперечать один одному, для виконання діє англійський текст.
Розбіжність залишається дефектом документації та блокує процесний або
продуктовий реліз.

## Історичні документи

Опубліковані release notes, manifests, evidence, checksums та інструкції,
прив’язані до незмінного продуктового тега, є історичними записами. Їх не
можна мовчки переписувати під нову матрицю компонентів. Замінена активна
інструкція отримує помітне legacy notice і посилання на чинну політику.

Наявні процесні документи `*_UK.md` збережено для матриці iVINS 1.0.0.0.
Нова робота виконується за канонічними документами з `docs/README.md`.

## Мова вимог

`MUST`, `MUST NOT`, `SHOULD` і `MAY` мають звичайне нормативне значення.
Документи повинні відрізняти випущену поведінку від запропонованої або
заблокованої цілі. Версію компонента можна включити до матриці iVINS лише
після появи її незмінного релізу та обов’язкових доказів.
