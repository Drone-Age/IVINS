# Політика версіонування iVINS

## Версія продукту

`VERSION` має формат `PRODUCT.MAJOR.MINOR.PATCH`, продуктовий тег —
`v<PRODUCT>.<MAJOR>.<MINOR>.<PATCH>`.

- **PRODUCT** — нове покоління продукту або ідентичність сумісності;
- **MAJOR** — несумісна поведінка чи інтерфейс кінцевого продукту;
- **MINOR** — зворотно сумісна функціональність або оновлення матриці;
- **PATCH** — зворотно сумісне виправлення чи перепакування.

Версія iVINS визначає одну перевірену матрицю точних component commits,
незмінних tags, Debian versions, artifacts, dependency repositories, hashes
і результатів gate. Вона не копіює версію компонента.

Перехід від монолітного `iros2-0` до split-пакетів `iros2j` вимагає нової
продуктової версії iVINS, оскільки змінюються install contract і формат
offline delivery. Метадані iVINS 1.0.0.0 залишаються незмінними.

## Версія процесу

`PROCESS_VERSION` незалежно використовує SemVer:

- **MAJOR** — несумісна зміна manifest schema або обов’язкового gate;
- **MINOR** — зворотно сумісна обов’язкова можливість чи автоматизація;
- **PATCH** — сумісне виправлення або уточнення.

Процесні теги мають формат `process-v<MAJOR>.<MINOR>.<PATCH>`. Якщо зміна
стосується продукту й процесу, обидва файли збільшуються, а обидва незмінні
теги створюються після проходження застосовних gate.

## Незмінність

Опубліковані tags, manifests, checksums, signed repository snapshots та gate
evidence незмінні. Дефектний реліз відкликають, але не переписують і не
перевикористовують. Виправлення отримує нову версію та повторює всі зачеплені
gate.
